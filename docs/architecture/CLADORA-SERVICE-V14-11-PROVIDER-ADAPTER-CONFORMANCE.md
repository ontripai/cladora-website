# SERVICE v1.4 provider adapter conformance

`SV-ADAPTER-BUNDLE-15` defines four pure consumer adapters. They validate full provider receipts and return either the unchanged, non-lossy verified receipt or a bounded decision containing only `status` and `code`. They do not query a source, mint a receipt, authorize an actor, mutate SERVICE state, or persist replay, audit, or outbox facts.

All four adapters require an exact current authority expectation assembled from a server re-read. The actor reference and positive safe authority version must match the receipt, and the authority outcome must still be allowed. The full receipt envelope binds contract/version and receipt identity, canonical source identity/version, Workspace, authority outcome, bounded provider result/reason, evaluation time, case-sensitive idempotency key, normalized input fingerprint, and idempotency binding identity. Source, Workspace, authority, replay, and specialized payload mismatches fail closed. Denial returns no receipt or source metadata and performs no write.

| Package | Canonical owner | Adapter in this bundle | Provider state on the base `main` | Runtime boundary |
|---|---|---|---|---|
| `COMM-DOC-SUBJECT-ADAPTER-01` | Communications and Vault/Documents | Validates `service-subject-link-adapter.v1` against the exact Request, reference, relation, audience, read authority, source version and replay fingerprint | `contract-only`; canonical Communications/Documents records exist, but no accepted receipt issuer implements this contract | Subject-link persistence and runtime issuance remain absent |
| `DOC-DELIVERY-EVIDENCE-01` | Vault/Documents | Validates `service-delivery-evidence-receipt.v1` against exact Order/stage and the complete unique evidence ID/version set; quarantined, deleted, unreadable and cross-Workspace evidence is denied | `contract-only`; document/evidence records exist, but no accepted receipt issuer implements this contract | Delivery mutation, receipt persistence and object access remain absent |
| `OPS-STAGE-WORKORDER-01` | Operations / OPS01 | Defines and validates `service-order-stage-work-order-adapter.v1` for one technical stage and one canonical versioned Work Order | `contract-only`; Work Order runtime exists, while the SERVICE stage binding provider is not accepted on `main` | Advisory stages do not invoke the adapter; Work Order completion never means delivery acceptance or settlement |
| `PF01-SERVICE-ACTION-PROJECTION-01` | Portfolio / PF01 | Validates `portfolio-service-action-projection-receipt.v1` for exact portfolio, Workspace, Order/version and action | `contract-only`; portfolio sources exist, but no accepted PF01 SERVICE projection receipt issuer is present on `main` | Ownership, mandate, Order state and projection persistence remain with their canonical owners |

`src/lib/customer/service-provider-adapter-contracts-v1.ts` is not imported by a route or runtime entry point. The conformance harness exercises complete envelopes, current-authority revocation, source and specialized stale versions, cross-Workspace and binding tamper, case-sensitive replay changes, private-data rejection, bounded provider conflict/unknown results, and zero mutation on denial. A future runtime package must inject accepted canonical providers, re-read authority in the transaction, serialize replay, and persist successful SERVICE effects atomically. This contract/test bundle provides no runtime acceptance.
