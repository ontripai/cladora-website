# SERVICE quote draft runtime 014

Adds coordinator-only management of non-binding drafts after contract 013. The distinct `services.quotes.manage` permission is bound to the existing `services_orders` module; request/read permissions never confer coordinator authority. No user, role assignment, activation or entitlement is granted by the migration.

The existing canonical workspace permission/context resolver supplies current actor, tenant and membership. Read returns only that workspace's latest 50 submitted requests and each request's latest 10 draft versions; the UI states these limits. Provider and beneficiary labels are scoped through the request, never a tenant-wide party picker. New writes also require a current unarchived beneficiary mapping and unarchived provider. Direct table and anonymous RPC access are revoked; RLS is enabled. Privileged RPCs have fixed search paths and canonical live authorization before data access.

This first runtime slice permits exactly one proposed payer: the verified beneficiary of the request. Other payers require the shared relationship/representation path and separate acceptance; references in a draft are not consent. Contract 013 remains able to validate future multi-payer proposals, but this RPC rejects them. No legal identity, ownership or vendor authority is inferred from a synthetic pilot person.

Each new draft pins the historical request catalogue revision, stores exact minor-unit total/currency/scope/expiry and records the acting coordinator membership. Versions are append-only with an update/delete guard and composite request FK. The request row lock allocates consecutive versions; same-key concurrent commands reconcile one response, different keys serialize into separate versions. Existing shared idempotency storage uses server-side actor/tenant fingerprint and a versioned namespace. Draft, audit, outbox and response commit atomically. Exact retries recheck live access/parties and can reconcile a committed draft after quote expiry; expiry still prevents a new draft. No draft can be accepted through these RPCs.

The same-origin JSON gateway rejects unknown query/body fields and returns private no-store responses with sanitized errors. RO/EN/FA UI snapshots uncontrolled inputs, converts decimal strings to minor units exactly using the shared currency registry, freezes uncertain commands, blocks double submission and ignores late replies after changing context/workspace or view. A confirmed write remains confirmed if history refresh fails.

No order, financial posting, payment, acceptance, Operations execution, AIRPROP or shared core function changes are introduced. Publication, independently authorized payer acceptance and execution remain subsequent runtime slices; tax treatment must be fixed before exposing commercial acceptance.

Validation runs actual migrations in isolated PostgreSQL, including two independent connections in CI. Database cases cover scoped authority, permission revocation, expired party link, exact amounts and replay, historical revision, injected actor/consent/finance fields, immutable versions, atomic audit failure and ACL/RLS. Mounted React tests cover all locales, exact expiry/amount, unknown result retry, denied/conflict paths, duplicate submission and obsolete responses. Existing catalogue/request and full application checks are retained.
