# Communications private-message subject provider v1

`communications-private-message-subject-provider.v1` resolves an existing private message for a transaction-scoped consumer. Communications remains the canonical owner of the message and participant state. Core remains the owner of current authority and the transaction host. The provider creates no message copy, authority projection, receipt ledger, audit store, outbox, or idempotency store.

The existing `communications.private_messages` row now carries a positive safe-integer `version` and a canonical `lifecycle_state` of `available`, `quarantined`, or `deleted`. Existing rows start at version 1 and `available`. Message identity is immutable. A body or lifecycle change must advance the version by exactly one; a version cannot change without one of those revisions. Physical deletion is forbidden, so delete/reinsert cannot reset version history or move an identifier to another Workspace.

`communications.resolve_private_message_subject_v1` is a stable, `SECURITY DEFINER` resolver with execution revoked from public application roles, including `service_role`. The Core transaction host owns invocation through its trusted database scope; this package adds no grant or runtime wiring. The resolver requires the actor already bound by Core authority to equal `auth.uid()`. The message unit must resolve through exactly one current `platform.workspace_property_bindings` row to the requested active Workspace, the exact Communications entitlement must be current, and the supplied context must cover the message unit. Missing, ambiguous, cross-Workspace, cross-scope, or unauthenticated requests share one bounded denial.

An accepted SQL result contains only the decision, message identifier and version, exact Workspace, lifecycle, and two booleans describing whether the calling participant is current or revoked. Expected stale, scope, lifecycle, and participant denials return one bounded decision row with all source fields null, so the surrounding transaction remains usable and performs no write. It never returns the body, sender, conversation, unit, membership identifier, profile, or another participant. A real PostgreSQL serialization failure remains an exception for the Core host's fresh-transaction retry loop.

The TypeScript provider directly implements the merged `CoreTransactionProvidersV2` surface and emits `core-transaction-provider-evidence.v1`; it does not define a second evidence type. Its subject binding is `message` / `subject_link`, and it consumes the transaction-bound `core-current-authority-decision-receipt.v1`. Authority denial or any actor, Workspace, attempt, command, aggregate, or transaction mismatch is rejected before SQL. The only issued statement is the resolver `SELECT`. Quarantined, deleted, revoked, stale, missing, and cross-Workspace sources return bounded Core evidence with no reference metadata. Wiring this provider into SERVICE composition or a public route remains outside this package.
