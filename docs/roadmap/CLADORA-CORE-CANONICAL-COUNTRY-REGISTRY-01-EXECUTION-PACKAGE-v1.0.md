# CORE-CANONICAL-COUNTRY-REGISTRY-01 execution package v1.0

Status: **`blocked_canonical_source_required`**
Contract: `CLADORA-CORE-CANONICAL-COUNTRY-REGISTRY-v1.0`
Owner: Core / Platform

## Blocking decision

Management must approve exactly one authoritative, redistributable and
immutable country-code source release, together with its provenance and
integrity evidence, before implementation begins. The decision must name the
publisher, dataset family, edition/version, acquisition reference, exact source
SHA-256, permitted storage/distribution boundary and verification method.

No engineering package may fill the gap with an inferred or manually composed
list. Until the decision is recorded, the public result is
`canonical_source_required`.

## Delivery sequence

1. **Source admission.** Acquire the approved bytes through the controlled
   supply-chain path. Verify the pinned digest and retain the approved evidence
   without placing private reviewer/signoff material in public outputs.
2. **Deterministic manifest.** Add a pinned generator with golden vectors. It
   must reject malformed rows, duplicates, `ZZ`, overlapping effective periods,
   missing dates and classifications outside `active`, `withdrawn` and
   `historical`. It must never derive codes from locale data.
3. **Core persistence migration.** Add immutable release and entry inventories
   under `platform`, initially populated only from the admitted generated
   manifest. Separate source-byte and normalized-manifest SHA-256 values.
4. **Database protection.** Enable RLS; deny `PUBLIC`, `anon`, `authenticated`
   and `service_role`; assign a canonical NOLOGIN owner; prevent UPDATE/DELETE,
   source rebind and overlapping matches. The execution role may not own the
   objects or reach the owner, superuser or BYPASSRLS through role membership.
5. **Typed lookup port.** Implement separate `current` and `historical` modes
   with no fallback, no inference, bounded metadata and
   `reusable_as_command_authority=false`.
6. **Disposable evidence.** Bootstrap all migrations from zero and prove exact
   active, withdrawn, historical, duplicate, unknown/`ZZ`, effective-date,
   source-integrity, RLS/ACL/ownership and zero-write behavior.
7. **Independent source and security review.** Review generated bytes against
   the admitted source, manifest hashes, immutability, catalog ownership and
   recursive memberships.
8. **Remote preflight and installation.** Require separate authorization. The
   pending set must contain only the reviewed registry migration(s). Installation
   does not grant product roles or activate a consumer.
9. **Consumer packages.** Property address entry, jurisdiction selection and
   AIRPROP may consume the accepted lookup only in separately reviewed packages.
   They cannot copy the inventory or add fallback country logic.

## Planned persistence invariants

The implementation review must prove:

- release identity and source hashes are immutable;
- `(registry_version, country_code, effective interval)` cannot be duplicated or
  ambiguous;
- current lookup accepts only an `active` entry in the one active release;
- historical lookup pins the exact release and instant and never upgrades;
- withdrawn and historical entries remain distinguishable and available only
  through historical mode;
- source bytes or an approved immutable source artifact remain auditable;
- the normalized database representation never substitutes for the pinned
  source-byte hash;
- all lookups are SELECT-only and emit no audit, outbox, idempotency or domain
  writes.

## Acceptance matrix

| Evidence | Required result |
| --- | --- |
| Approved source and exact digest | Match before generation or migration |
| Duplicate code/effective overlap | Bounded denial; migration/test fixture rejected |
| Unknown uppercase token and `ZZ` | `COUNTRY_CODE_UNKNOWN`; zero writes |
| Current active entry | Exact version/status/interval/fingerprints |
| Current withdrawn or historical entry | Denied without fallback |
| Exact historical release and instant | Exact historical classification; no upgrade |
| Historical gap or missing release | `COUNTRY_HISTORY_UNAVAILABLE` |
| Locale/language/currency/timezone/phone/IP/Workspace default | Ignored; never lookup input |
| RLS/ACL/owner/membership uncertainty | Fail closed |
| Repeated lookup | Same bounded decision; zero durable writes |

## Explicit exclusions

This execution package does not authorize a Property/address country mutation,
country move, Country Pack, tax/accounting rule, currency, postal regex, payment
rail, legal approval, role grant, route, seed from an unapproved source, Remote
apply or runtime activation.

PostgreSQL, connected Remote validation and Production acceptance remain
**`NOT_RUN_NOT_PASS`**.
