# Guide no-document installation / bounded recovery v1

This is an inactive target-specific adoption packet, not migration replay or
application activation. Parent is the containing delivery's exact Parent. The
original55000/ROLLBACK proposals and accepted QFW/Auth/Request code remain intact.
Use only Platform's admitted transport and private target/credential custody.
A marker/GUC/JSON profile is correlation, never execution authority.

Order: preflight (read-only) ->00-fixed-roles ->05-owner-delegations ->
08-audience-dependency ->10-guide-core ->20-save-relation ->verify (read-only).
Each numbered unit has its own BEGIN/COMMIT. Do not wrap the chain in a new BEGIN.
00/05 require the observed, explicitly admitted lifecycle custodian capability;
its name is not proof.10/20 and08 use the ordinary Core installer. No assumption
that hosted postgres is superuser is made. If the required lifecycle/owner-side
capability is unavailable, STOP and request exactly that delegation through
Platform; never grant installer an extra role, grant option or bypass.

Before dispatch bind exact target/backend/database OID/PG17, transport identity,
private plan SHA256 and exact unit bytes/hash. The target must already contain the
accepted canonical Core closure. Guide schema/roles are absent at initial entry;
shared *_at helper owner/body/search_path/closed pre-ACL must match actual handoff.
Refresh prestate when executing: historical observation is not current admission.
Read preflight results privately. Missing role privileges are NULL, not allow/deny.

00 creates ONLY the two fixed Guide roles and one SET-only edge.05 grants only
schema auth USAGE and fixed EXECUTE boundaries; it preserves every existing
function body/owner/security/search_path, role edge and default privilege.
08 adopts only the real canonical handover-lineage read helper when absent;
its existing canonical table is required. Existing exact helper is checked and
reused; mismatch/overload STOP. No handover writer, role assignment or fake table.
10 creates Guide schema/tables/helpers, narrow executor rights/RLS and registry
identities. Registry is not a Workspace module activation, entitlement or positive
permission assignment. No Storage/scanner or S01 runtime is installed.
20 adopts the exact canonical typed save/C03 binding with FORCE RLS, original
actor/Context predicates, immutable receipt and deferred same-transaction check.
All explicit document targets must be JSON null; document references are closed.

Before COMMIT, an acknowledged same-backend ROLLBACK removes that unit's DDL/ACL.
It does not roll back any earlier unit's independently acknowledged COMMIT.
Timeout/cancel/socket loss/error during COMMIT is UNKNOWN. Preserve first error,
unit payload/plan identity, physical backend/attempt and actual terminal evidence;
STOP before the next unit. No blind resend, repair-as-applied, replacement IDs or
unqualified DROP/REVOKE is permitted.

Recovery uses a NEW admitted read-only observer to compare exact known pre/post
objects, owners, helper hashes, function/table/column ACL/grantors, role graph,
RLS/policies/constraints and registry records. A complete poststate catalog is
installation evidence; it is not a business receipt or proof of current authority.
Missing/mixed/ambiguous state remains UNKNOWN/HOLD. Resume a failed rolled-back
unit only after an explicit exact-prestate decision;00/05 are not replayed merely
because a later unit failed. The packet has no destructive automatic uninstaller.

Committed Guide/C03/audit/outbox/save data is NEVER rollback cleanup, fixture
purge or a reason to drop a schema/role. Any eventual fixture removal or product
retention/abandonment has its own authorized contract. Readonly GET does not
manufacture a receipt. Existing published Request and other domain rights stay
outside this packet.

The disposable PG17 test uses private new credentials, official provider schema
initialization and an exact accepted Core foundation derivative; it has no
connection to the shared target. Its receipts distinguish SQL execution/readback
from transport ReadyForQuery evidence (not captured by psql), application Auth,
currentness/concurrency, UI and restart. Cleanup ACK covers only resources created
by that labelled run. Do not execute the disposable harness on an existing stack.
