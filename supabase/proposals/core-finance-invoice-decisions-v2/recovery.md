# Private reader v2 — source-only execution and recovery contract

No execution authorized. Native role/ACL/RLS/capacity/window admission belongs to
Platform/custodian. This packet creates no login, role, membership, positive GRANT,
Auth fixture, data, approval, receipt, transaction host or public facade.

Order / per-unit COMMIT:
1. Verify existing Core1f serializer/origin immutability, Core30 canonical fresh-time
   closure and real Finance75 source body pins. Historical622 source acceptance is
   not invoice-v2 acceptance. Do not replay historical migrations.
2. `reader.sql` installs three private owner-only INVOKER functions atomically.
   Existing same-name/overload or positive default ACL is STOP, not IF NOT EXISTS.
   Installer needs actual schema CREATE/USAGE and separately authorized ownership;
   no SET/ADMIN/membership/owner delegation is assumed or manufactured.
3. Platform supplies actual runtime principal/receipt hashes. Render the SIX exact
   role-specific policy statements offline with the renderer. Review target/role,
   owner/delegation/default/inherited ACL and existing policies. Renderer output is
   a proposal, not proof/admission. Install the policies in one separate transaction
   only after that authority is independently granted. Existing actor policies and
   shared Auth remain untouched. No positive grants are in either payload.
4. Platform separately admits minimum rights: schema USAGE, exact function EXECUTE,
   SELECT review tables, UPDATE(id) for row locks only. No other UPDATE, INSERT,
   DELETE, TRUNCATE or sequence rights for review tables. Restrictive WITH CHECK
   false fences deny even unchanged-id business updates. Other source/C01/Finance
   role/ACL/RLS closure is real observed input, not implied by this column privilege.
5. Run preflight/verify catalog proposals under an admitted private observer and
   configured actual runtime-role selector. Then separate native tests under the
   actual runtime principal, not the installer/owner. Native callback may only use
   existing Core C01/C03 transport and real Finance75 routines.

Timeouts: installer/preflight/verify 5s lock,30s statement, transaction-local;
reader requires existing Core lock<=5s and statement<=10s, both positive, and
SERIALIZABLE lock-capable transaction. SQL READ ONLY is incompatible with row locks.
Timeout/cancel/connection loss is STOP/UNKNOWN, no partial rows or automatic retry.
Existing C03 alone decides bounded40001 retry and atomic mutation/receipt/audit/
outbox. No command/receipt is generated by this reader or its recovery.

Install failure: positive ROLLBACK and ReadyForQuery I on the same backend settles
that unit only. If COMMIT ACK is unknown, stop before the next unit and reconcile
exact routine body/security/owner/ACL and six policy role/USING/WITH CHECK tuples
using authorized read-only catalog observation. Do not retry CREATE/repair-as-applied.
A complete function unit with missing policy/grant admission remains NOT_READY.
No automatic DROP, policy removal, owner fallback, role swap or RLS disabling.
Recovery of an active deployment requires a reviewed successor/admission window;
removing a function/policy used by another transaction is not automatic rollback.
Previously committed business effects and original UNKNOWN command identities,
keys/body/receipt/TTL are not rewritten or undone by installer rollback.

Four transaction-local selectors are restored before the last canonical check on
success; SQL statement/transaction failure rolls their changes back through the
existing host. They convey only invoice/cycle/action selection, never an allow
flag. Target-row canonical denial aborts the scan instead of yielding a filtered
subset that could become falsely complete after a later time-based grant.

Native gates: compile exact three definitions and deparsed policy expressions on
PG17; real source row-lock UPDATE USING behavior; id-only privilege/write-fence
negative; different actor origins across tasks; actor-only/restrictive policy
rejection; missing/zero rows; expiry/revoke and future reactivation during waits;
40001 identity to existing host; timeout/UNKNOWN cleanup; two connections and
immutable-writer/source lock order. No tests were executed against PG/Auth/target.
DDL/helper/role/policy changes must be excluded from the admitted campaign window;
upstream PG17 policy locking assumptions do not independently prove a managed
provider or modified-server binary. Source, installation and native remain distinct.
